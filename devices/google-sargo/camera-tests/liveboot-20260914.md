# Sargo liveboot camera trial — 14 September 2026

Camera image quality is still unaccepted. This trial uses the designated test
phone and a disposable USB-root liveboot; the storage host remains connected.
The selected capture path is **libcamera**. The Megapixels application and its
packaging are out of scope for this PR and are retained only in the local
archived branch.

## Completed

- Booted a coherent `7.1.2-0.pocketfed.sdm670.11.fc46.aarch64` kernel/DTB/module
  bundle containing the LC898219XI lens power-sequence correction. Systemd
  handoff passed with enforcing SELinux, matching modules and an overlay root.
  This establishes boot infrastructure, not camera capture.
- Configured private Wi-Fi and key-authenticated SSH access in the fixture.
  Access credentials, host keys and raw device logs are excluded from this PR.
- Installed libcamera/IPA/tools `0.7.2-4.fc46` for the selected capture path.
- Verified the actual evdev Volume Up and Volume Down capabilities; the generic
  readiness gate's 37 host regressions pass. No capture is currently armed.

## Camera enumeration issue

CCI initially failed probing with `deferred probe timeout, ignoring dependency`
and error `-110`. CAMSS existed, but neither sensor nor the lens was registered.
After all CCI suppliers were bound and available, one explicit bind of the
unbound CCI controller succeeded. IMX363, IMX355 and LC898219XI then appeared,
and the strict power check reported all three suspended with no camera handles.

This was a recovery in the running trial; the initial boot did **not** pass
camera enumeration. The `.11` bundle already carries the CAMCC provider for the
CCI power domain (`CONFIG_SDM_CAMCC_845=m`, DTB compatible `qcom,sdm845-camcc`),
but CAMCC registered after the deferred-probe timeout. A one-line initrd
early-module correction is prepared in the liveboot harness profile
(`camcc_sdm845`) as draft PR #67 stacked on #61, with no command-line timeout
change. It remains **boot unvalidated**: a subsequent boot must confirm that
CCI, both sensors and the lens enumerate on their own.

## Historical Megapixels evidence

Before the user selected libcamera, a Megapixels 2 trial reached real rear
preview and saved three DNGs at 4032x3024, but the application crashed in its
postprocessing step before writing any JPEG; the strict camera release check
passed afterwards. That path is now out of scope and its code is removed from
this PR (retained only in the local archived branch). Those DNGs are not a
usable-JPEG acceptance result.
