## Current finding

**A plausible FPC/QSEE path exists, with concrete missing Linux interfaces.** The stock trusted app and Android HAL are present on this phone. PocketFed does not currently expose the sensor's reset/IRQ control or a legacy QSEECOM userspace application workflow. Installing fprintd or removing the QSEECOM machine allowlist check alone would not provide fingerprint support.

The missing application transport/loader/listeners were the stopping point for the 10 September feasibility pass; their implementation is now underway. During that initial 10 September pass, the phone was inspected over the tailnet while being carried; no reset, pin change, module load, TA invocation, package/service/authentication change, mount, partition write or reboot was performed. On 11 September Sam separately authorized private local analysis of specific stock firmware/library copies; those copies remain outside the repository.

## Architecture and existing implementations

- The [stock board DT](https://android.googlesource.com/kernel/msm/+/refs/heads/android-msm-bonito-4.9-android12L/arch/arm64/boot/dts/google/sdm670-b4s4-fingerprint.dtsi) and [GPLv2 FPC platform driver](https://android.googlesource.com/kernel/msm/+/refs/heads/android-msm-bonito-4.9-android12L/drivers/input/misc/fpc_fingerprint/fpc1020_platform_tee.c) provide a concrete reset/IRQ reference. The driver sends no sensor commands. `fpc,fpc1020` identifies the driver family; the fitted silicon revision and physical secure SPI controller remain unverified. The only live Linux SPI device is RT5514 audio.
- Current [QSEECOM kernel clients](https://github.com/samcday/linux/blob/38bef8725fa90dfb2be5a457eb75c656b1e45f0a/drivers/firmware/qcom/qcom_qseecom.c) only cover an already-loaded UEFI app. The [SCM allowlist](https://github.com/samcday/linux/blob/38bef8725fa90dfb2be5a457eb75c656b1e45f0a/drivers/firmware/qcom/qcom_scm.c) is not the only gap. Installed `CONFIG_QCOMTEE=m` is also not the answer by itself: [qcomtee uses the separate smcinvoke object protocol](https://docs.kernel.org/tee/qtee.html).
- [Wrobelda's legacy QSEECOM implementation](https://github.com/wrobelda/goodix-fp-spi-linux), [kernel branch](https://github.com/wrobelda/linux/tree/qcom-qseecom-tee), and [qsee-supplicant](https://github.com/wrobelda/qsee-supplicant) are useful transport/loader/listener candidates. The author reports complete fingerprint operation on an SM8250 Goodix device. The kernel work is out of tree; its Goodix protocol and hardware driver do not establish FPC compatibility.
- [Current blueline FPC notes](https://forge.caseytunturi.com/Fimeg/SouveraineOS/src/branch/public/docs/tasks/44-fingerprint-fpc1020.md) report loading the same TA name and initializing/arming the sensor. This is a close protocol lead, not demonstrated Sargo enrollment/matching. The detailed linked Pixel3Arch protocol source was not retrieved. Its temporary raw-IRQ PAM bridge must not be treated as biometric authentication. The Sargo TA's retained dynamic symbols have now been recovered independently.
- [Fairphone 6 fingerprintd](https://forgejo.catcrafts.net/Catcrafts/fingerprintd) offers another native lifecycle/testing reference, but uses Focaltech/newer QTEE and is not a Sargo driver.

## Implementation progress — 11 September

- The exact stock FPC wrapper, auxiliary-pointer fixup, initialization/capture sequence, enrollment/identify operations, database operations and enrollment-token checks have been decoded. Native protocol/TEE transport tests pass on the host and ARM64, including malformed replies and failure propagation. The capture-readiness diagnostic passed ARM64 [COPR 10973664](https://copr.fedorainfracloud.org/coprs/build/10973664), with verified RPM signatures, but has not run on the phone.
- The adapted legacy QSEECOM transport supports this ELF64 firmware and explicit common-library loading. A native reset/IRQ companion and Sargo DT node are prepared in kernel `.10`, based on camera `.9`. Local kernel/module linking and Sargo DT checks passed. The isolated **COPR kernel trial is [10973618](https://copr.fedorainfracloud.org/coprs/build/10973618)**; its ARM64 build succeeded, and signatures/digests of all seven runtime RPMs are verified against the configured kernel COPR key. Live boot remains untested.
- The patched **ARM64 qsee-supplicant trial [10973582](https://copr.fedorainfracloud.org/coprs/build/10973582) succeeded**. It includes a shared-library loader, readiness/error handling and tests. No proprietary firmware is bundled.
- Native libfprint FPC enrollment/matching/storage/cancellation support is implemented for offline testing. The ARM64 package passed [COPR 10973705](https://copr.fedorainfracloud.org/coprs/build/10973705) after fixing the simulated hardware boundary for Fedora link-time optimization. Production optimization remains enabled, and all selected tests pass. Recognition must come from the TA's identify result and requested gallery; an IRQ never constitutes authentication. Android biometric stores are excluded.
- The stock FPC TA requires a genuine challenge-bound Gatekeeper HAT. Private analysis of Sam-authorized stock firmware/library copies confirms Sargo's older fixed-field Gatekeeper format, rather than the later Qualcomm CBOR format. The root-only broker and durable credential store are implemented for offline review, with fault-injection and peer-identity tests. Its production backend still returns `EOPNOTSUPP`. The additional privately authorized stock library has now resolved the exact Keymaster version handshake and unpadded Gatekeeper message layout; native integration and device validation remain. The TA accepts version configuration once per loaded instance, so a repeated success cannot prove or repair earlier settings. No credential stores, templates, raw signing keys or proprietary artifacts are published.
- Final ARM64 desktop trial builds passed: corrected [Phosh 10973752](https://copr.fedorainfracloud.org/coprs/build/10973752), [GNOME Control Center 10973640](https://copr.fedorainfracloud.org/coprs/build/10973640), and [scoped PAM helper 10973641](https://copr.fedorainfracloud.org/coprs/build/10973641); downloaded RPM signatures are verified. Phosh has a separate cancellable fingerprint PAM flow with a root worker for homed's privileged active-home reference. GCC allows enrollment when the optional GDM settings schema is absent. Independent image comparison caught an earlier Phosh package regression: its supplied PAM file replaced the working Fedora policy with pam_unix-only authentication. That image was rejected. Corrected Phosh 1.5 preserves the byte-identical working policy and retains all 45 tests; the outer image also preserves the base PAM file. All live desktop tests remain.
- SELinux is enforcing on the inspected phone. Offline inspection of the candidate's compiled policy confirms that fprintd lacks access to the default labels for the new FPC and public TEE nodes. A separate minimal policy candidate now compiles and passes offline access/path-boundary checks and independent review. It is not loaded or included in the masked image. Actual device labels, enforcing operation and future broker-socket access remain to be verified.
- Recovery preparation must replace the boot template's embedded DTB as well as kernel/initramfs; the prior camera trial's unchanged-DTB path is insufficient. The current deployment/overrides, temporary added packages and existing recovery pins have been inventoried before any staging. A local image was proved identical to the booted base through its OCI configuration and all 114 rootfs layer digests. Offline image assembly preserves exact live extras and initially masks fprintd, qsee-supplicant and the Phosh fingerprint socket. The corrected local image (`83cc5287c9ae`) passed the full image checks and independent comparison of its kernel/DTB/initramfs, exact 17 runtime packages, unchanged unrelated packages, PAM and existing unit/policy content. All 107 initramfs module paths match the working base. Phosh, GCC and libfprint also passed loading/linking checks in a disposable ARM64 container. The fingerprint services remain masked; no broker or new SELinux policy is included. This is a preparation artifact, not an operational enrollment stack. No image has been staged or published.
